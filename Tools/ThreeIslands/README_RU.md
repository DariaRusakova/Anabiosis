# Три острова — версия 1.2, текстуры моделей и разнообразие

Подготовлена расстановка из **953 mesh actors** из ассетов проекта UE 5.7.4. Версия 1.2 сохраняет корректные исходные материалы и восстанавливает текстуры шести неполных FBX-импортов из их собственных карт. Новая `.umap` создаётся самим Unreal при запуске сборщика в Windows. В Linux выполнены проверки данных и предварительная визуализация в Blender; новая версия 1.2 в Unreal здесь не запускалась.

Предыдущая версия 1.1 уже успешно собрана пользователем в `Build_003`: Windows-отчёт содержит `success: true`, 950 объектов и 439 проверок коллизий. Этот отчёт относится к версии 1.1, а не к текущим изменениям.

## Запуск в Windows

1. Сохранить работу и закрыть Unreal Editor.
2. В корне проекта дважды нажать **`Build_Three_Islands.bat`**.
3. Дождаться сборки. Скрипт находит движок по `EngineAssociation` проекта в реестре Windows. Если движок не найден, ввести его корневую папку — ту, внутри которой лежит `Engine`.
4. После успешного сохранения откроется редактор с новой картой. После существующей `Build_003` сборщик выберет следующий свободный номер, обычно **`/Game/LevelDesign/ThreeIslands/Build_004/L_ThreeIslands_004`**. Предыдущие варианты и ручные правки сохраняются.
5. Дождаться компиляции шейдеров и нажать **Play → Selected Viewport**, запуск с Default Player Start. Персонаж появится на ангельском острове.

Если папка `Binaries/Win64` ещё не содержит модуля проекта, запуск сначала вызывает стандартный `Build.bat` для существующего `AnabiosisEditor`. Для этого нужен уже установленный Windows C++ toolchain. При ошибке сборки сначала открыть исходный проект привычным способом и добиться его запуска, затем повторить запуск островов.

Отчёт: `Saved/ThreeIslands/latest_build.json`. Успешное завершение обозначается `success: true` и путём `map`. Полный лог: `Saved/ThreeIslands/UnrealBuild.log`. При ошибке отчёт содержит traceback; карта предыдущей успешной сборки сохраняется. Скрипт проверяет идентификатор текущего запуска, поэтому старый успешный отчёт не принимается за результат нового.

Для явного выбора движка:

```powershell
.\Build_Three_Islands.bat -EngineRoot "D:\Epic Games\UE_5.7"
```

Можно собрать без последующего открытия редактора: добавить `-NoOpen`.

Ручной запуск внутри уже открытого UE: сохранить текущую карту, затем **Tools → Execute Python Script** и выбрать `Content/Python/build_three_islands.py`. Если Python ещё не включился после изменения `.uproject`, перезапустить редактор.

### Исправление ошибки материалов в сборщике 1.1

В двух первых Windows-запусках сборка остановилась с `Cannot connect material socket: Input`. Причина — использование имени C++-поля вместо имени входа графа материала. Теперь первый вход и первый RGB-выход выбираются штатным пустым селектором API, а имена остальных входов запрашиваются у Unreal. Исправлено также аналогичное подключение `ComponentMask` в материале пола. Все подключения выходов материала проверяют результат API.

Все варианты материалов создаются перед открытием новой карты и расстановкой геометрии. В отчёте есть `builder_revision`, этап `stage` и сведения о текущем материале/объекте при ошибке. Текущая версия сборщика — `three-islands-builder-1.2`.

Регрессионные тесты соединения входов и сохранения модельных текстур запускаются командой `python -m unittest discover -s Tools/ThreeIslands -p 'test_*.py' -v`. Они не заменяют запуск Unreal.

## Текстуры в версии 1.2

- У корректно импортированных GLB-моделей сохранены исходные material slots: цвет, Normal, Roughness, Metallic и Emissive, заданные их материалами.
- У кристалла, половины арки, светлой колонны `pillar_lp`, лестницы, скалы `cliff_rock1` и базальта исходные FBX-материалы были без текстур либо с `WorldGridMaterial`. Для них создаются **отдельные материалы из собственных карт конкретной модели**, с её исходной UV-развёрткой. Общая тонированная текстура камня на модели больше не назначается.
- Base Color и Emissive подключены напрямую. Normal сохраняется как normal map. Для скалы `rock2_ORM` каналы R/G/B используются как AO/Roughness/Metallic.
- Часть карт Roughness/Metallic/AO/ORM в исходном импорте ошибочно отмечена как sRGB. Сборщик создаёт копии этих карт внутри новой `Build_NNN/Textures` с линейным чтением. Исходные текстуры не меняются.
- Светлый, серый и тёмный материалы остаются на геометрических примитивах пола, балок и парапетов. Цвета импортированных моделей берутся из собственных текстур.
- Перед сохранением проверяется назначение всех материал-слотов моделей. В отчёте появились `restored_source_materials`, `linear_data_texture_copies` и `model_material_slot_checks`.

## Планировка и визуальный характер

| Остров | Пространство и ориентир | Палитра |
|---|---|---|
| Ангельский, слева | Светлое святилище, парные галереи, колонны разной высоты, светлые скалы и каменные башенки | Светлый пол, родные текстуры моделей, голубые световые акценты |
| Нейтральный, в центре | Разделённые террасы, двухэтажная разрушенная аркада, поваленная колонна, **стилизованный камень в центре** | Серый пол, несколько видов серых и светлых скал |
| Демонский, справа | Бастион с тройной аркой, частично разрушенная коллонада, упавшая балка, базальтовые пики | Тёмный пол, базальт, лавовые камни, красные световые акценты |

Под каждым островом — сильно увеличенный кристальный камень `crystal-stone-rock/source/Mesh`, развёрнутый остриём вниз, и дополнительные кристальные осколки. Импортированная вместе с ним плоскость `Mesh_ncl_1` не используется. Геометрия пола ровная; открытые края и стены террас прикрыты каменной отделкой.

На каждом острове есть скалы, колонны, лестницы, арки и коллонады. Арки собраны из двух половин исходного ассета; балки коллонад опираются на колонны. Укрытия стоят небольшими группами, с низкими камнями около 1,2 м и высокими заслонами около 2 м. Главные террасы имеют по два подхода; боковые платформы ангельского и демонского островов — по одному лестничному входу.

Основания островов имеют разные пропорции и повороты осколков; более длинное основание демонского острова усиливает его силуэт. Новая задняя аркада нейтрального острова служит декорацией: для её тяжёлого mesh не включается треугольная коллизия. Для боя и укрытий остаются основные колонны, арки, скалы и парапеты с коллизией.

Острова примерно 64 м в поперечнике, расстояние между центрами 85 м. Между ангельским и нейтральным, а также между нейтральным и демонским — по два каменных моста. Ширина свободного прохода между парапетами 3,6 м. Небольшой перепад мост/пол — 2 см, чтобы пересекающиеся поверхности не мерцали. Высоты террас: 3 / 3,6 / 6 м.

## Что уже проверено

- Существование всех 41 уникальных исходных mesh/texture packages, включая карты восстановленных FBX-материалов; уникальность имён и воспроизводимость расстановки.
- Доступность 17 основных точек по консервативной схеме проходов с радиусом персонажа 34 см и высотой 192 см.
- Восемь сценариев с закрытием одного лестничного подхода к главным террасам: альтернативный путь остаётся.
- Композиция через рендеры из исходных FBX/GLB проекта. См. `Preview/overview.png`, `angel.png`, `neutral.png`, `demon.png`, `top.png`.
- 15 тестов политики текстур и соединений материалов. Предыдущие виды сохранены в `Preview/v1_1`.
- Синтаксис Python; используемые ключевые UE API сверены с официальной документацией 5.7.

Во время Windows-сборки предусмотрены **реальные UE collision traces** для полов, мостов, лестниц и центрального прохода арок. Сборщик измеряет ступени отдельно от перил и определяет направление лестницы и зеркальность половины арки после FBX-импорта. Для новой версии 1.2 эти проверки и проверка текстур в Unreal **ещё не запускались**. Blender показывает композицию и приближение PBR-материалов; итоговые UE-шейдеры и освещение могут выглядеть иначе.

## Первый игровой обход

1. От места появления пройти через входную арку, обойти обе группы укрытий и подняться на святилище. Спуститься второй лестницей; проверить отсутствие застреваний у ступеней, колонн и площадок.
2. Посетить обе боковые террасы. Проверить видимость противника за низкими и высокими камнями с обычной камеры персонажа.
3. Перейти на нейтральный остров по одному мосту. Обойти центральный стилизованный камень с обеих сторон, подняться на обе террасы и спуститься внутренними лестницами.
4. Перейти на демонский остров, пройти все лестницы и арки. Вернуться на ангельский по другой паре мостов.
5. Проверить, что парапеты не цепляют капсулу, светлый остров не пересвечен, а на тёмном читаются противник и укрытия.
6. Для повторного обхода закончить PIE клавишей Escape и нажать Play. На открытых обрывах можно упасть; после падения перезапустить PIE.

Это окружение для дальнейшего боевого тестирования с существующим first-person GameMode. Новые враги, правила победы, автоматический респавн, NavMesh для ботов и боевая логика не добавлялись. Баланс укрытий, ощущения движения, FPS и итоговое освещение проверяются в Windows.

## Редактирование и сохранность проекта

В World Outliner все новые объекты разложены по `ThreeIslands / Angel|Neutral|Demon / …`. Сохранены камеры `Review_Overview`, `Review_Angel`, `Review_Neutral`, `Review_Demon`: выбрать камеру и включить Pilot для осмотра.

Сборщик создаёт обычные StaticMeshActor и сохраняемые материалы. После создания карта редактируется вручную; Python для её игры не нужен. Исходные `.umap`, модели, материалы, C++, настройки стартовой карты и GameMode проекта не переписывались. Коллизии настраиваются на копиях mesh assets внутри `Build_NNN`; восстановленные материалы и линейные копии карт создаются там же и назначаются только новым объектам.

В `Anabiosis.uproject` добавлено включение двух встроенных editor plugins: `PythonScriptPlugin` и `EditorScriptingUtilities`. Исходный descriptor сохранён в `Backup/Anabiosis.uproject.before-three-islands`.

Данные расстановки: `Content/Python/three_islands_layout.py`. Сборка UE: `Content/Python/build_three_islands.py`. Для Linux-проверки данных: `python Tools/ThreeIslands/validate_layout.py`. Для обновления предварительных рендеров при установленном Blender: `blender -b -t 8 --python Tools/ThreeIslands/preview_offline.py`.

Исходные ассеты и их происхождение перечислены в `assets.manifest.json`; внешние ассеты не скачивались. Условия уже имеющихся ассетов сохранены, независимо лицензии не проверялись.

Документация Epic: [Python в Unreal Editor](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python?application_version=5.7), [LevelEditorSubsystem 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/LevelEditorSubsystem?application_version=5.7), [EditorActorSubsystem 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/EditorActorSubsystem?application_version=5.7).
